# Goal

Execute commands securely in an isolated Sandbox (Docker) to prevent accidental damage to the host system (e.g. `rm -rf`) due to hallucination, and capture the exact standard output and error to self-correct code.

# Instructions

1. **Verify Environment**:
   - Check if Docker is installed (`docker --version`). If not, warn the user.
   - Check for Python (`python --version`) or Node.js (`node --version`) to run the wrapper script.

2. **Prepare Execution**:
   - Extract the command to run, the Docker image (defaults to `ubuntu:latest` if not specified), and the timeout (defaults to 10000 ms).
   - Ensure you are passing the current workspace directory to the script so it can be mounted as read-only (`ro`).

3. **Execute Wrapper**:
   - Run the appropriate wrapper script, which handles the `docker run` orchestration.
   - Python: `python .agents/skills/execute-in-sandbox/scripts/sandbox.py "<command>" "<docker_image>" "<timeout_ms>"`
   - Node: `node .agents/skills/execute-in-sandbox/scripts/sandbox.js "<command>" "<docker_image>" "<timeout_ms>"`

4. **Analyze Output**:
   - Read the exact stdout/stderr returned by the script.
   - If tests fail, use the stderr traceback to autonomously refactor and fix the code before presenting the final result.

# Conventions

- **Read-Only Mount**: The script automatically mounts the workspace directory as `ro` (Read-Only) to maximize safety. No compilation artifacts will be saved back to the host.
- **Segregated Output**: The script will clearly indicate `--- STDOUT ---` and `--- STDERR ---` to help the AI parse the results.

# Constraints

- Do NOT attempt to run interactive commands.
- ALWAYS respect the timeout to prevent infinite loops from hanging the agent's turn.
- The working directory mapped into the container is fixed at `/workspace`.
